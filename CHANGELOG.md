# Changelog

## 0.2.6 (2026-10-18)

a SimpleSubCommand can now say four things a command library had to say beside it: a list of words (`systemctl stop U1 U2`, `mkdir -p A B C`), a line with no word of its own so its first value leads (`chown OWNER PATH`), a program alone (`hostname`), and the exit statuses a line names (`systemctl is-active`'s 0 active, 3 inactive). each is a new key or a type the derive used to refuse, so every struct that compiled on 0.2.5 generates the same code: across the full parity runs the only difference is that a misspelt `#[subcommand(..)]` or `#[arg(..)]` key now lists the new keys among the known ones.

### lists

- a field was one value: positional pushed `self.field.clone()`, so a `Vec` field could not compile: [src/simple_subcommand.rs L226-L238](https://github.com/jameshuntt/simple_impl_derive/blob/980e6143ea9c7ef265bd6fb8170ccd1b8a064201/src/simple_subcommand.rs#L226-L238). a `Vec` field is a list now, with no new key: `#[arg(positional)]` gives one word per value and `#[arg(kv = "-p")]` gives `-p value` per value, and its setter adds a list after the values already there (simple_impl_quote_kit 0.3.3). `#[builder(init_required)]` takes one value, so on a `Vec` it is SHELL5007: [src/simple_subcommand.rs L334-L337](https://github.com/jameshuntt/simple_impl_derive/blob/d5c7da8ca2473d47b3404e02d629c78d4a3637eb/src/simple_subcommand.rs#L334-L337).
- `#[arg(each = path)]` checks the value, or every value of an `Option` or a `Vec`, with a `fn(&str, &OsStr) -> CommandValidationResult` given the field's name and the value, so one check like "a plain word" serves every field. it is written as code or as a string, as 0.2.5's expression keys are. `#[arg(min = N)]` is the fewest values a `Vec` takes; on anything else it is SHELL5008, and below 0 SHELL5009: [src/simple_subcommand.rs L352-L376](https://github.com/jameshuntt/simple_impl_derive/blob/d5c7da8ca2473d47b3404e02d629c78d4a3637eb/src/simple_subcommand.rs#L352-L376), [src/vocabulary.rs L174-L191](https://github.com/jameshuntt/simple_impl_derive/blob/d5c7da8ca2473d47b3404e02d629c78d4a3637eb/src/vocabulary.rs#L174-L191).
- the checks run after the struct's rules, as one generated method the contract calls the way it calls a `#[validate(with)]`, so no rule variant was added: [src/simple_subcommand.rs L91-L97](https://github.com/jameshuntt/simple_impl_derive/blob/d5c7da8ca2473d47b3404e02d629c78d4a3637eb/src/simple_subcommand.rs#L91-L97), [src/simple_subcommand.rs L176-L227](https://github.com/jameshuntt/simple_impl_derive/blob/d5c7da8ca2473d47b3404e02d629c78d4a3637eb/src/simple_subcommand.rs#L176-L227).

### a line with no word of its own, and a leaf that is its own root

- `segment` was required and always pushed first: [src/simple_subcommand.rs L100-L106](https://github.com/jameshuntt/simple_impl_derive/blob/980e6143ea9c7ef265bd6fb8170ccd1b8a064201/src/simple_subcommand.rs#L100-L106), [src/vocabulary.rs L130-L133](https://github.com/jameshuntt/simple_impl_derive/blob/980e6143ea9c7ef265bd6fb8170ccd1b8a064201/src/vocabulary.rs#L130-L133). `#[subcommand(no_segment)]` leaves it out, so the fields come right after the root's program: `chown OWNER PATH` is a leaf under the same `chown` root as `chown -R OWNER PATH`. `segment` and `no_segment` together are refused. with neither, and no `program`, the segment is missing as it always was, in the same words: [src/simple_subcommand.rs L229-L243](https://github.com/jameshuntt/simple_impl_derive/blob/d5c7da8ca2473d47b3404e02d629c78d4a3637eb/src/simple_subcommand.rs#L229-L243), [src/vocabulary.rs L130-L149](https://github.com/jameshuntt/simple_impl_derive/blob/d5c7da8ca2473d47b3404e02d629c78d4a3637eb/src/vocabulary.rs#L130-L149).
- a leaf only ran under a CompositeShell root. `#[subcommand(program = "hostname")]` makes it its own root: it gets `CompositeShellRoot`, `CompositeShellCommand` and its setters itself, so `Hostname` or `Kill::default().pids(["12"])` runs with no root struct. a segment still goes after the program (`program = "systemctl", segment = "stop"`), and the leaf still goes under any root as a leaf does.
- a unit struct was SHELL5003, named fields required: [src/simple_subcommand.rs L115-L119](https://github.com/jameshuntt/simple_impl_derive/blob/980e6143ea9c7ef265bd6fb8170ccd1b8a064201/src/simple_subcommand.rs#L115-L119). a unit struct is a line with no arguments now: `#[subcommand(segment = "daemon-reload")] struct DaemonReload;`, `#[subcommand(program = "hostname")] struct Hostname;`: [src/simple_subcommand.rs L252-L258](https://github.com/jameshuntt/simple_impl_derive/blob/d5c7da8ca2473d47b3404e02d629c78d4a3637eb/src/simple_subcommand.rs#L252-L258).

## 0.2.4 (2026-10-15)

This is the collector release. Every derive gets one `SynBuffer`, every check pushes into it and keeps going, and the hard fail only happens at the end through `finish_with` once it went through all of the checks, so one compile shows every independent mistake instead of just the first one. A check that depends on something already reported (an attribute that didn't read, a field that already failed) skips instead of echoing it. All the codes are in one `liaise_codes!` table in diag.rs now and the dead liaise path is gone.

### the collector

- `expand` ran `parse_struct_and_fields(input)?` and then each emitter with `?`, so the first broken thing was the only thing you ever saw: [src/simple/expand.rs L3-L19](https://github.com/jameshuntt/simple_impl_derive/blob/177ac11fb2265ef0ee64bf1e195a824388db577b/src/simple/expand.rs#L3-L19). now there's one `SynBuffer` for the whole derive, the parse and the emitters all run, each emitter skips only the fields whose own problems were already reported, and `finish_with` at the end is the one hard fail: [src/simple/expand.rs L3-L33](https://github.com/jameshuntt/simple_impl_derive/blob/f00d80d46e64025a8f559d8fc3a52b8b5ae0802e/src/simple/expand.rs#L3-L33). `SynBuffer` and `ensure!` come in from liaise_proc_macro: [src/simple/mod.rs L25-L25](https://github.com/jameshuntt/simple_impl_derive/blob/f00d80d46e64025a8f559d8fc3a52b8b5ae0802e/src/simple/mod.rs#L25-L25). proof, a parse problem, a shell problem and an ordering problem in one compile: [src/simple/collect_tests.rs L70-L85](https://github.com/jameshuntt/simple_impl_derive/blob/f00d80d46e64025a8f559d8fc3a52b8b5ae0802e/src/simple/collect_tests.rs#L70-L85).
